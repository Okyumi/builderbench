# BuilderBench DCC port + sgcrl ablations

Last updated: 2026-06-09

## 1. What this change adds

### 1.1 BuilderBench (this repo)

- `rl/impls/decomposed_networks.py` — Flax implementation of the Decomposed
  Contrastive Critic (DCC) family. Five (or six) trainable groups:
  `b_shared`, `h_phi`, `h_dyn`, `phi_task`, `psi_shared` (+ optional
  `psi_task`, `psi_proj`).
- `rl/impls/continual_crl_dcc.py` — new driver mirroring
  `continual_crl.py` but using DCC. Same SLURM-friendly scaffolding
  (auto-resume from per-task checkpoints, wandb wiring, no interactive
  prompts).
- `rl/impls/experiment_configs_dcc.py` — ablation grid enumerator
  (mirrors the API of `experiment_configs.py`).
- `rl/impls/draft_dcc.sh` — SLURM launcher for the DCC ablations; reuses
  the same env / CUDA setup as `draft_4.sh`.

No existing files (continual_crl.py, knowledge_pool.py, rl_metrics.py,
draft_4.sh, experiment_configs.py) were modified. Baseline runs keep
behaving exactly as before.

### 1.2 sgcrl (Sawyer / single-goal CRL)

- `contrastive/decomposed_networks.py` — added `combine_mode` (`add` |
  `concat`) and `goal_encoder_mode` (`shared` | `projected`). When a goal
  projection is active the goal-encoder params live inside a bundle dict
  `psi_params = {'psi': ..., 'psi_proj': ...}`, so the existing
  `DecomposedTrainingState` and learner do not need new fields and
  optax flows through unchanged.
- `contrastive/continual_config.py` — new fields `combine_mode` and
  `goal_encoder_mode` with documented defaults.
- `run_continual_contrastive.py` — flags + plumbing, plus the
  rl-metrics fix described in §5.

## 2. Sawyer vs. BuilderBench: relevant differences

| Concern | sgcrl (Sawyer)                                 | BuilderBench                              |
|---------|------------------------------------------------|-------------------------------------------|
| Framework | Acme + Haiku + JAX                           | Flax + JAX (no Acme) on Brax-style env    |
| Critic API | `ContrastiveNetworks` with `repr_fn` / `actor_repr_fn` | `SA_encoder` / `G_encoder` Flax modules called explicitly |
| Goal | future state from same trajectory (geometric-discount sampling, p=0.5 negatives) | env-provided `target_goal`; `achieved_goal` used as future goal in replay |
| Obs layout | `[s(11), one-hot(K), g(11), one-hot(K)]` | padded to `UNIFIED_OBS_DIM=51` (10 prefix + 13×3 cube blocks + 2 suffix); separate `target_goal` of dim 9 |
| Stable indices for dyn loss | `select_stable(s')`  (gripper xyz + gripper open) | cube positions: 3 coords per cube × MAX_CUBES = 9 dims (= UNIFIED_GOAL_DIM) |
| Score function | inner-product (SGCRL default) or negative L2 | negative L2 (Brax CRL default) |
| Continual loop | acme builder + learner; per-task replay buffer | imperative for-loop in `continual_crl.py`; replay buffer recreated per task |
| Package versions | older Brax + Haiku; not Brax 3.x | jax[cuda12] ≥ 0.6.2, mujoco-mjx ≥ 3.3.6, flax ≥ 0.10.5, distrax ≥ 0.1.5 |
| `jax.tree_map` | available | removed; use `jax.tree.map` (already fixed in commit `5f5670b`) |
| CKA pool API | `contrastive/knowledge_pool.py` | `rl/impls/knowledge_pool.py` (Flax pytrees) |
| Actor heads naming | `mean_head`, `log_std_head` | identical (so CKA `adapt_heads_only` mode works the same way) |

Implication for porting: I duplicated the driver rather than sharing
code. The cost is ~1k lines of similar control flow; the benefit is
that the CKA grid driver stays bit-identical and any future Flax/Brax
API drift cannot creep into both code paths through a shared import.

## 3. Running DCC on BuilderBench

### 3.1 Smoke test (single seed, short steps)

```bash
cd rl/impls
python continual_crl_dcc.py \
    --seed 1 \
    --task_sequence cube-1-task1,cube-2-task1 \
    --steps_per_task 1000000 \
    --base_steps 1000000 \
    --num_envs 256 \
    --no-track \
    --no-save_checkpoint
```

This runs the algorithm without wandb or checkpoints. Use to verify the
JIT cache survives the task boundary and the dyn loss numbers look
sensible.

### 3.2 Full ablation sweep on HPC

```bash
cd rl/impls
python experiment_configs_dcc.py --list      # show all 27 configs (9 ablations × 3 seeds)
python experiment_configs_dcc.py --total     # 27
sbatch draft_dcc.sh                          # launch the array job
```

`draft_dcc.sh` dispatches each row in `experiment_configs_dcc.py` to
the right runner (`continual_crl.py` for baseline rows,
`continual_crl_dcc.py` for DCC rows). To shrink the sweep, edit
`SEEDS` in `experiment_configs_dcc.py`.

### 3.3 Manual single-config run

```bash
python continual_crl_dcc.py \
    --use_dcc \
    --dcc_combine_mode concat \
    --dcc_goal_encoder_mode partial_shared \
    --dcc_use_dyn \
    --dcc_dyn_weight 1.0 \
    --task_sequence "$TASK_SEQUENCE" \
    --steps_per_task 50000000 \
    --base_steps 50000000 \
    --wandb_group dcc_ablations \
    --wandb_name_tag dcc_concat_partial_seed1
```

## 4. Config flags

| Flag                          | Default     | Effect |
|-------------------------------|-------------|--------|
| `--use_dcc`                   | true        | Master switch. Disables the driver if false. |
| `--dcc_use_dyn`               | true        | Toggle the dynamics auxiliary `L_dyn`. |
| `--dcc_dyn_weight`            | 1.0         | μ multiplier on `L_dyn`. |
| `--dcc_combine_mode`          | add         | `add` (z_sa = z_shared + z_task) or `concat` (z_sa = [z_shared; z_task]). |
| `--dcc_goal_encoder_mode`     | shared      | `shared`, `task_specific`, `partial_shared`, `decomposed`, `projected`. |
| `--dcc_phi_task_width`        | 256         | Width of the task-specific encoder. |
| `--dcc_phi_task_depth`        | 4           | Depth of the task-specific encoder. |
| `--dcc_carry_shared`          | true        | If false, every group is reset each task (ablation sanity check). |

## 5. Note on the sgcrl rl-metrics logging issue

When `critic_mode='decomposed'`, `ContinualDecomposedLearner.q_params`
intentionally returns `None`. The previous version of
`run_continual_contrastive.py` short-circuited the rl-metrics block on
that signal and printed a one-time skip notice. As a result, all
representation metrics (`actor/weight_norm`, `critic_sa/feature_rank`,
NRC, dormancy) were unavailable for DCC runs.

What I checked:

- The learner exposes the right components: `b_shared_params`,
  `h_phi_params`, `phi_task_params`, `psi_params`, `h_dyn_params`. The
  bundle is also returned by `get_variables(['critic'])[0]`.
- `rl_metrics.compute_all_metrics` only needs `networks.repr_fn(params,
  obs, action) -> (sa_repr, g_repr, _)` and `networks.actor_repr_fn`.
  It tolerates `critic_hidden_repr_fn=None` (rl_metrics.py lines
  184-186).
- The actor's `actor_repr_fn` from the standard `networks` object is
  reusable as-is, because DCC keeps the actor architecture identical.

Fix applied (commit message: `sgcrl: log rl_metrics for DCC via a
synthetic networks shim`):

- Build a `SimpleNamespace` shim with `repr_fn` backed by
  `decomp_nets.apply_sa_repr` and `decomp_nets.apply_psi`,
  `critic_hidden_repr_fn=None`, and `actor_repr_fn` taken from the
  existing `networks`. Cache it on the learner so we don't allocate a
  new closure every metrics tick.
- Pass `learner.get_variables(['critic'])[0]` (the dict bundle) instead
  of `learner.q_params` when on the decomposed path.

Limitations:

- `critic_sa/nrc2` (NRC2 on hidden critic features) and
  `critic_sa/dormant_ratio` on the pre-projection hidden layer are not
  computed for DCC because the decomposed body has TWO heads off the
  same hidden representation (h_phi and h_dyn). The standard NRC2 needs
  one final-projection weight matrix; we'd have to pick either
  `h_phi.weight` or compute NRC2 twice. Left as a follow-up; the
  frequent metrics (weight norm, entropy, gini) and other occasional
  metrics (feature_rank on sa_repr/g_repr, NRC1, dormancy on the
  output features) are all logged.
- The shim path triggers on `learner.q_params is None`; nothing else
  changes, so persistent / CKA / reset runs are bit-identical.

## 6. sgcrl ablation matrix

| Flag                  | Default | Variants exposed |
|-----------------------|---------|------------------|
| `--dyn_aux_weight`    | 1.0     | `0.0` disables `L_dyn`; `--dyn_aux_after_task0=0.0` keeps it on at base task only |
| `--combine_mode`      | add     | `add`, `concat` (auto-attaches a goal projection) |
| `--goal_encoder_mode` | shared  | `shared`, `projected` (adds the goal projection even with combine=add) |
| `--phi_task_width`    | 256     | grid: 64, 128, 256, 512 |
| `--phi_task_depth`    | 4       | grid: 2, 4, 8 |

The richer goal-encoder modes (task_specific / partial_shared /
decomposed) are exercised on the BuilderBench port for now and not in
sgcrl. The reason is the cross-cell comparability of the Sawyer
results: each new psi variant introduces a new optimiser-state slot
that has to be plumbed through the checkpoint files, breaking
cross-task resume. On BuilderBench the checkpoints are simpler
single-file pickles per task, so the variants stay self-contained.

## 7. Proposed experiments for a main-conference push

Numbers below assume the BuilderBench 12-task sequence and the
sgcrl 10-task Sawyer sequence at 8e6 steps/task / 50e6 steps/task,
3 seeds, A100-80G HPC, TASKS_PER_GPU=2.

| # | Experiment                       | Benchmark | Variants                                      | Metric(s)                                          | Purpose                                                            |
|---|----------------------------------|-----------|-----------------------------------------------|----------------------------------------------------|--------------------------------------------------------------------|
| 1 | DCC vs CRL on BuilderBench       | BB        | baseline_persistent, baseline_reset, dcc_add_shared | per-task success, AUC, forward-transfer, forgetting | The headline cross-benchmark result. Show DCC ≥ best baseline.    |
| 2 | Dynamic loss on/off              | BB + Sawyer | dcc_add_shared vs dcc_no_dyn                | per-task success, L_dyn curve, weight_norm        | Quantify how much L_dyn contributes vs the per-task encoder alone.|
| 3 | Combine mode                     | BB + Sawyer | dcc_add_shared vs dcc_concat_shared         | per-task success, sa_repr feature_rank, NRC1      | Does concat preserve task-private info better than additive sum?  |
| 4 | Goal-encoder mode                | BB        | dcc_goal_{shared, task_specific, partial_shared, decomposed, projected} | per-task success, psi weight_norm, g_repr feature_rank | Establish where the shared-vs-task trade-off lives on the goal side. |
| 5 | phi_task size                    | BB + Sawyer | dcc_add_shared @ width ∈ {64,128,256,512}, depth ∈ {2,4,8} | per-task success, gradient norm, fwd transfer    | Find the smallest task encoder that recovers DCC performance.     |
| 6 | Forward + backward transfer scan | BB        | dcc_add_shared, baseline_persistent          | success at first eval, retention at end of curriculum | Plot transfer matrix; complements per-task AUC.                  |
| 7 | Plasticity stress test           | Sawyer    | dcc_add_shared vs reset/persistent in 20-task extension | dormant_ratio, feature_rank, NRC1 trajectories   | Convince reviewers DCC keeps the network plastic past 10 tasks.   |
| 8 | Sparse-reward stress             | BB        | dcc_add_shared, baseline_persistent          | per-task success on cube-3-task{2,4,5}            | Hardest BB tasks; tests dense → sparse generalisation.            |
| 9 | Robustness to task order         | BB        | dcc_add_shared, baseline_persistent, 3 shuffled orderings | per-task success, sum of forgetting              | Show DCC's gains are not order-specific.                          |
| 10 | Wall-clock + memory              | BB + Sawyer | all DCC variants                            | sps, GPU mem, env steps/sec                       | Cheap to add; reviewers always ask.                               |

Realistic budget: experiments 1, 2, 3, 5 (3 seeds) + 4 (1 seed for an
initial scan) fit comfortably in two HPC weeks at 2 jobs/GPU. Defer
6–10 until after a first internal cut on 1–5.
